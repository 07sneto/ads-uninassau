Desenvolvimento de Aplicações para Internet - Aula 24-08



Cliente > faz a solicitação
Servidor > recebe * processa * responde (Aplicação Back-end)



# O caminho de uma pagina Web

	Navegador > Servidor > Back-end > Servidor > Navegador

# Request x Response

	# Request . Requisição
	
	Método = GET/POST/PUT/PATCH/DELETE
	URL = caminho do recurso
	Headers = metadados da comunicação
	Body = dados enviados, quando necessário

	# Response . Respota

	Status = 200/201/404/500...
	Headers = metadados da resposta
	Body = dados retornados
	JSON = formato comum em APIs

# HTTP e HTTPS

Hypertext Transfer Protocol
	
	Regras para comunicação entre cliente e servidor
	
	HTTP = Comunicação Web Baseada em requisição e resposta.
	HTTPS = HTTP + proteção por criptografia/TLS
	
	Uma base para construir APIs

# Método mais usados

	GET = Consultor / obter
	POST = Criar / enviar
	PUT = Substituir / atualizar
	PATCH = Atualizar parcialmente
	DELETE = Remover


# Códigos de status: a resposta do servidor

	2xx > Sucesso
	
		200 OK
		201 Created

	4xx > Problema na requisição
		
		400 Bad Request
		401 Unauthorized
		404 Not found (Dica: 404 não significa que "a internet caiu". Significa que o recurso solicitado não foi encontrado.)

	5xx > Erro no servidor
	
		500 Internet Server Error

# JSON: um formato comum em APIs

JavaScript Object Notation

	Uma forma estruturada de representar e transportar dados.
	
	Exemplo:
	{\n "id: 10,\n "nome:
	"Ana",\n "curso": "ADS"\n}

	O cliente pode receber esses dados e utilizá-los na interface.
